# Телеграм-бот для anfinances — дизайн

Дата: 2026-08-10
Статус: утверждён владельцем продукта
Предшественник: [фундамент](2026-08-10-currency-foundation-design.md) (пункты 3.3 и 3.6 — до этой работы)

## 1. Контекст

Ввод операций через веб требует открыть сайт, найти форму, заполнить поля. Мичем в
брошюре «Вам нужен бюджет» настаивает: трата записывается в телефон **в момент
траты**, за секунды, иначе привычка не приживается. Телеграм-бот закрывает именно
этот разрыв.

Сверх ввода бот отвечает на вопросы по данным («сколько осталось», «почему в этом
месяце всё уходит») и рассуждает о финансах.

### Место в общем плане

1. **Фундамент** (отдельный документ) — до бота только два пункта: инвариант знака
   в БД и периодическое обновление курсов.
2. **Бот** — настоящий документ.
3. **Цели** — накопления к сроку, стабфонд, отслеживание правила «жить на доход
   предыдущего месяца» как сущностей. Отдельный подпроект после бота.
4. **Остаток роадмапа** — гигиена валют, AF-019, AF-031, AF-007, интерфейсные
   мелочи, инфраструктура 11.x, бэкапы 0.1.

### Профиль пользователя

Один пользователь, режим `single_user`. Основная валюта — рубль, есть настоящий
сумовый счёт, несколько рублёвых карт и наличные. Дерево категорий с
подкатегориями. Таймзона хранится в профиле.

## 2. Решения

### Р-1. Один агент с инструментами, а не режимы

Первая редакция дизайна разделяла «разобрать фразу в операцию» и «ответить на
вопрос» на два режима. Отвергнуто: между ними нужен классификатор, а классификатор —
самостоятельный источник ошибок.

Вместо этого — один агент, которому даны инструменты записи и чтения; он сам
решает, что вызвать. Фраза «потратила 300 на кофе, а сколько у меня вообще
осталось» обрабатывается за один заход: запись, чтение, связный ответ.

### Р-2. Бот — обычный клиент API, без доступа к базе

Бот ходит в anfinances по HTTP на `backend:8000` во внутренней docker-сети. Прямого
подключения к PostgreSQL у него нет и не будет.

Соседство в одном compose-стеке — про удобство эксплуатации, а не разрешение лезть
в базу. Всё, что бот умеет, ограничено тем, что разрешает API.

### Р-3. Размещение — немецкий VPS вместе с сайтом

`anfinances.ru` → 188.68.49.26, netcup GmbH, Германия (хост `formybots`). Проверено
фактически: `api.telegram.org` отвечает 302, `api.anthropic.com` и
`api.openai.com` — 401, то есть достижимы и не блокируют по географии.

Отдельный VPS (`bobobots`) отвергнут: даёт вторую машину и второй деплой без выгоды,
раз география не мешает.

### Р-4. Аутентификация — вход по учётным данным единственного пользователя

Бот вызывает `POST /auth/login` с `SINGLE_USER_EMAIL` и `SINGLE_USER_PASSWORD`
(уже в GitHub Secrets), держит access-токен в памяти, перелогинивается по
истечении или по первой 401.

Отвергнуты сервисные токены: новая таблица, эндпоинты и экран ради одного
потребителя на той же машине. Пересмотреть перед AF-026, когда откроется публичная
регистрация.

### Р-5. Модель — Claude Opus 5 на среднем усилии

`claude-opus-5`, `thinking: {type: "adaptive"}`, `output_config: {effort: "medium"}`.

Нагрузка двугорбая: большинство фраз тривиальны («кофе 300»), меньшинство требует
настоящего рассуждения («сколько я могу потратить до зарплаты с учётом платежа по
кредиту»). Дешёвая модель на втором горбе даёт уверенный неправильный ответ — худший
исход в разговоре про деньги.

Вместо выбора между моделями — понижение усилия. На Opus 5 низкие уровни `effort`
заметно сильнее, чем у предыдущих моделей. Это даёт стоимость уровня Sonnet при
опусовском потолке и без классификатора «простой вопрос или сложный».

Оценка: порядка одного-трёх центов за обращение с учётом кэширования, три-шесть
долларов в месяц при пятнадцати фразах в день.

### Р-6. Счёт — по умолчанию, кнопки при настоящей неоднозначности

Цена ошибки со счётом выше, чем с категорией: неправильная категория портит отчёт и
это видно, неправильный счёт разводит баланс с реальностью и обнаруживается через
неделю.

Порядок разрешения, сверху вниз, первое сработавшее правило выигрывает:

1. Счёт назван во фразе («со сбера», «альфа картой», «наличными») — берём его.
2. В выведенной валюте у пользователя ровно один счёт — берём его.
3. Последние операции в этой категории единодушно шли с одного счёта — берём его.
4. Валюта совпадает с валютой счёта по умолчанию (`BOT_DEFAULT_ACCOUNT_ID`) —
   берём счёт по умолчанию.
5. Иначе — ряд кнопок со счетами, один тап.

На практике шаги 1–4 закрывают почти всё: рублёвая трата без указания счёта уходит
на основную карту, сумовая — на единственный сумовый счёт. Шаг 5 срабатывает редко —
когда в валюте несколько счетов и ни история, ни умолчание не помогают.

### Р-7. Категория — дерево в контексте плюс история

Категории должны определяться точно: на них держатся бюджеты и вся аналитика.

- Всё дерево лежит в кэшируемом контексте **в виде путей** («Еда → Кофейни»), а не
  плоским списком.
- Для незнакомых формулировок — поиск по прошлым операциям: куда пользователь
  относил это же слово раньше. Повторяет его собственную классификацию, а не
  общепринятую, и со временем становится точнее.
- Карточка показывает полный путь, ошибка видна сразу.
- Переспрашивает двумя кнопками только при настоящей неоднозначности между двумя
  категориями, а не на каждой фразе.

### Р-8. Голосовые не хранятся

Аудио уходит в OpenAI на распознавание, возвращается текст, файл удаляется
немедленно. Расшифровка в комментарий операции не пишется.

### Р-9. Межвалютную операцию бот не досчитывает

При переводе между счетами в разных валютах бот **обязан** получить обе фактические
суммы и не имеет права вывести вторую по рыночному курсу. Именно пара реальных сумм
фиксирует настоящий курс пользователя — это ключевое свойство модели переводов в
anfinances (`src_rub / amount_to` запекается как фактический курс).

## 3. Архитектура

```
Telegram → бот (Python, отдельный сервис в compose-стеке)
             ├─ голос → OpenAI Whisper → текст
             ├─ текст → Claude Opus 5 с инструментами
             └─ инструменты → anfinances API (backend:8000)
```

### 3.1. Технологии

- **Python** — тот же язык, что и бэкенд; те же `uv`, типизация, `ruff`, `mypy`.
- **aiogram 3** — async-native клиент Telegram, ложится на тот же стиль, что
  async FastAPI.
- **`anthropic`** — официальный SDK. Агентный цикл через
  `client.beta.messages.tool_runner` с инструментами, объявленными декоратором
  `@beta_tool`: цикл «вызов → выполнение → результат → продолжение» ведёт SDK.
- **`openai`** — официальный SDK, только для распознавания речи (`whisper-1`,
  имя модели в настройках, чтобы менять без правки кода).
- **`httpx`** — обращения к anfinances API.

### 3.2. Набор инструментов

Запись:

| Инструмент | Эндпоинт |
| --- | --- |
| `create_expense` | `POST /transactions` |
| `create_income` | `POST /transactions` |
| `create_transfer` | `POST /transfers` |
| `update_transaction` | `PATCH /transactions/{id}` |
| `delete_transaction` | `DELETE /transactions/{id}` |

Чтение:

| Инструмент | Эндпоинт |
| --- | --- |
| `list_accounts` | `GET /accounts` |
| `list_categories` | `GET /categories` |
| `get_capital` | `GET /summary/dashboard` |
| `get_cashflow` | `GET /summary/cashflow` |
| `get_by_category` | `GET /summary/by-category` |
| `get_budget` | `GET /budgets` |
| `list_transactions` | `GET /transactions` |
| `get_credits` | `GET /credits` |
| `get_money_age` | новый — см. 3.4 |

Инструментов на удаление счетов, категорий и кредитов, на правку настроек, валют и
начального баланса **нет**. Это осознанная граница, а не упущение.

### 3.3. Кэширование промпта

В кэшируемый префикс идут: системная инструкция, описания инструментов, список
счетов и дерево категорий путями. Волатильное (текущая фраза, время) — после точки
кэширования.

Список счетов и дерево категорий обновляются раз в сутки и при явном изменении
через веб; менять их чаще нельзя, потому что любое изменение префикса обнуляет кэш.

### 3.4. Новый эндпоинт в бэкенде: возраст денег

`GET /summary/money-age` — единственная доработка бэкенда в этом подпроекте.

Считает по существующим операциям: доход предыдущего календарного месяца против
расходов текущего, и буфер — какую долю текущих расходов покрывает прошлый доход.
Это четвёртое правило ВНБ («жить на доход предыдущего месяца») в виде числа.

Ни таблиц, ни миграций. Экран во фронтенде в этот подпроект не входит — величину
показывает бот.

### 3.5. Настройки

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN_FINANCE` | Токен бота. Имя отличается от `TELEGRAM_BOT_TOKEN`, который уже занят ботом уведомлений о деплое. |
| `TELEGRAM_ALLOWED_USER_IDS` | Белый список Telegram-ID через запятую. |
| `ANTHROPIC_API_KEY` | Ключ Anthropic. |
| `OPENAI_API_KEY` | Ключ OpenAI (только распознавание речи). |
| `BOT_DEFAULT_ACCOUNT_ID` | Счёт по умолчанию — шаг 4 разрешения счёта (Р-6). |
| `BOT_QUIET_HOURS` | Часы тишины, по умолчанию `23-9`. |
| `BOT_BUDGET_MEETING_DAY` | День месяца для бюджетного совещания. |

Все — через GitHub Secrets в `.env` на сервере тем же шагом деплоя, что и остальные.

## 4. Поведение

### 4.1. Доступ

Сообщения от Telegram-ID вне `TELEGRAM_ALLOWED_USER_IDS` получают вежливый отказ и
**не доходят ни до распознавания, ни до модели** — ни расхода, ни утечки.

Юзернейм бота угадывается; без белого списка любой набредший сможет и читать
финансы, и писать операции.

В личных чатах Telegram идентификатор пользователя совпадает с идентификатором
чата, поэтому тот же список даёт адрес для проактивных сообщений — отдельного
состояния хранить не нужно.

На старте бот читает `GET /auth/me` и берёт оттуда таймзону: она нужна и для
«вчера», и для часов тишины.

### 4.2. Запись операции

Оптимистичная запись: операция создаётся сразу, в ответ приходит карточка.

```
Записала: Еда → Кофейни — 300 ₽, Альфа карта, сегодня
[Исправить]  [Удалить]
```

Кнопки — `callback_query`; идентификатор операции хранится в данных кнопки.

Бот переспрашивает **только** в этих случаях:

- **Межвалютная операция без второй суммы** (Р-9) — спрашивает, сколько пришло.
- **Счёт неоднозначен** (Р-6, шаг 4) — ряд кнопок со счетами.
- **Категория неоднозначна между двумя** (Р-7) — две кнопки.
- **Сумма или тип операции неоднозначны** — «перевела Маше пятёрку» может быть
  пятью тысячами или пятью сотнями, расходом или переводом.

**Операция задним числом в нерублёвой валюте**: бот предупреждает, что курс взят
текущий (курсов на прошлые даты система не хранит — см. Р-3 фундамента), и даёт
ввести свой курс вручную.

### 4.3. Ответы на вопросы

Бот отвечает по данным, полученным инструментами, а не по общим соображениям.
«Сколько осталось» — число с разбивкой по счетам. «Почему в этом месяце всё уходит» —
конкретные категории с суммами и сравнением с прошлым месяцем.

Про накопления бот считает и рассуждает уже в этой версии; чего он не может —
запомнить цель и следить за ней. Это подпроект 3.

### 4.4. Проактивные сообщения

Три сценария, у каждого свои тормоза.

**Бюджетное совещание** — раз в месяц, в день из `BOT_BUDGET_MEETING_DAY`, в
таймзоне пользователя. Итоги месяца, что выбилось из плана, предложение разложить
деньги на следующий. Мичем настаивает, что ритуал должен быть коротким и приятным,
поэтому это несколько строк и вопрос, а не простыня.

**Напоминание записать траты** — если операций не было двое суток. Не чаще раза в
двое суток; не повторяется, пока пользователь не ответит или не запишет что-нибудь.

**Предупреждение о перерасходе** — проверяется **сразу после записи расхода**, а не
по расписанию: бот только что создал операцию в этой категории, ему дешевле всего
тут же посмотреть бюджет. Не чаще одного предупреждения на категорию за месяц.

Общие правила: тишина в часы из `BOT_QUIET_HOURS` по таймзоне пользователя; каждое
проактивное сообщение отключается командой.

Первые два сценария — фоновые задачи asyncio в процессе бота, по образцу
периодического обновления курсов из фундамента. Третий планировщика не требует.

### 4.5. Голосовые

Аудио → OpenAI Whisper → текст → дальше как текстовое сообщение. Файл удаляется
сразу после получения расшифровки, независимо от того, чем закончился разбор.

## 5. Отказы

Ни один сбой не должен приводить к тихой потере операции.

| Что отказало | Поведение |
| --- | --- |
| anfinances недоступен | Прямо сообщает, что не смог записать. Не делает вид, что записал. |
| Whisper недоступен | Просит написать текстом. |
| Anthropic недоступен | Сообщает, что не смог разобрать фразу, предлагает записать через веб. |
| API вернул ошибку валидации | Показывает причину человеческим языком. |
| Токен протух | Молча перелогинивается и повторяет запрос один раз. |

## 6. Тестирование

| Что | Как проверяется |
| --- | --- |
| Белый список | Сообщение от чужого ID не доходит до распознавания и до модели |
| Разбор фразы | Набор фраз на русском → ожидаемые вызовы инструментов, с заглушками вместо API |
| Р-6 | Все четыре шага разрешения счёта, включая ветку с кнопками |
| Р-7 | Выбор листа, выбор родителя, подсказка из истории, ветка с двумя кнопками |
| Р-9 | Межвалютный перевод без второй суммы приводит к вопросу, а не к досчёту |
| Задним числом | Валютная операция прошлой датой сопровождается предупреждением о курсе |
| Проактивность | Часы тишины соблюдаются; напоминание не повторяется; перерасход не чаще раза в месяц на категорию |
| Голос | Файл удалён после расшифровки и после сбоя расшифровки |
| Отказы | Каждая строка таблицы раздела 5 |
| `GET /summary/money-age` | Юнит-тесты расчёта, включая месяц без дохода и первый месяц истории |

Существующие проверки остаются зелёными: `ruff`, `mypy`, `pytest`, `tsc -b`,
`eslint`, `vitest`, `pnpm build`. Бот добавляет свои `ruff`, `mypy`, `pytest` в CI.

## 7. Критерии готовности

- С телефона голосом записывается расход, приходит карточка с полным путём
  категории и счётом, кнопки «Исправить» и «Удалить» работают.
- Фраза с явным счётом («со сбера») попадает на этот счёт.
- Фраза без счёта при неоднозначности даёт кнопки, а не догадку.
- Межвалютный перевод без второй суммы вызывает вопрос.
- Вопрос «сколько осталось» отвечается числом по данным.
- Чужой Telegram-ID не получает ничего, кроме отказа.
- Голосовые файлы на сервере не остаются.
- Три проактивных сценария работают и соблюдают тишину.
- Все проверки зелёные.

## 8. Что дизайн сознательно не делает

- Не хранит цели накопления, стабфонд и историю «возраста денег» как сущности —
  это подпроект 3.
- Не даёт боту удалять счета, категории и кредиты, менять настройки, валюты и
  начальный баланс.
- Не хранит голосовые файлы и расшифровки.
- Не заводит историю курсов (решение Р-3 фундамента); вместо этого предупреждает.
- Не добавляет экран «возраста денег» во фронтенд — только эндпоинт.
- Не вводит сервисные токены — вернуться перед AF-026.
